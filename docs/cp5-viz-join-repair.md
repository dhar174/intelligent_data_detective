## Correction and no-task handoff

The active W14H transformation validates dictionary envelopes with canonical
`VisualizationResults.model_validate`, then collects their actual children.
It retains instance/list compatibility and handles per-worker envelopes.
Figure identity, title, description, type, style, path and response flags are
preserved. Duplicate IDs and equivalent paths are not counted twice.

Malformed or unfinished metadata and missing required figures raise errors
instead of becoming empty success results. A previously completed inventory
cannot be replaced by an empty result (important because completion uses a
boolean-OR State reducer). A genuinely empty, unrequested inventory does not
claim completion.

A second source-grounded defect occurs with `viz_tasks=[]`: the baseline join
clears `viz_results`, while the evaluator skips and the report orchestrator
consumes that cleared channel. The corrected join appends only missing report
metadata through the existing reducer on that path. With pending tasks it
preserves the existing clear/evaluate/repopulate sequence; a controlled real
evaluator test ensures this does not append each figure twice.

The no-task evaluator keeps the inventory and reports `not_evaluated` with
`last_agent_finished_this_task=False`; it does not invent a quality assessment.
Canonical routing and State reducers are unchanged. The existing route still
accepts completed nonempty visualization inventory; skipped quality evaluation
is not converted into a model evaluation.

Recursive PNG discovery is removed. Structured results never require discovery.
An explicit path-only contribution must be an existing nonempty PNG inside the
current runtime's `run_dir`; it cannot replace structured metadata. No unrelated
or historical files are scanned to meet a count threshold.
